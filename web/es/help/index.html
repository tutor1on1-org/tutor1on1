Inicio rápido

Usar Tutor1on1 según el rol.

Los profesores publican y administran cursos. Los estudiantes solicitan inscripción, descargan contenido aprobado y reciben guía, práctica y repaso de errores según su progreso.

Flujo profesor

Publicar y personalizar cursos.

  1. Inicie sesión como profesor o registre una cuenta de profesor.
  2. Cree o cargue una versión local del curso.
  3. Suba el bundle validado al marketplace.
  4. Apruebe solicitudes de inscripción de estudiantes.
  5. Revise en la página del profesor el progreso, errores recurrentes y sesiones sincronizadas de cada estudiante.

Flujo estudiante

Inscribirse y estudiar a su ritmo.

  1. Inicie sesión como estudiante o registre una cuenta de estudiante.
  2. Abra el marketplace y solicite inscripción en un curso.
  3. Espere la aprobación del profesor.
  4. Descargue el bundle aprobado del curso.
  5. Abra el curso e inicie una sesión Learn o Review que siga su progreso.

Crear cursos con AI

Convertir PDF, PPT o apuntes en una carpeta de curso Tutor1on1.

Use un agente AI fuera de la app para reformatear materiales existentes. Tutor1on1 valida, carga, publica y permite ajustar un KP a la vez.

  1. Ponga PDF, PPT, Word, hojas de ejercicios y notas de respuestas en una carpeta fuente. Si son escaneos, haga OCR y revise fórmulas manualmente.
  2. Pida primero a Codex solo el esquema contents.txt. Apruebe orden, títulos y granularidad de los KP antes de crear archivos.
  3. Pida a Codex crear la carpeta de salida. Cada id de contents.txt necesita su <id>_lecture.txt. Los bancos opcionales usan <id>_easy.txt, <id>_medium.txt y <id>_hard.txt.
  4. Cargue la carpeta en Tutor1on1 como profesor. Si aparece un error de archivo faltante o id inválido, péguelo en Codex y pida reparar la carpeta.
  5. Después de cargar el curso, use clic derecho en un KP y AI edit content para ajustes pequeños de lección o preguntas.

Codex web

  1. Cree una tarea: Generate Tutor1on1 course folder from teaching materials.
  2. Suba los archivos PDF/PPT/Word.
  3. Prompt: Read the uploaded materials and propose a Tutor1on1 contents.txt outline. Use dotted ids like 1, 1.1, 1.2. Do not generate files yet. Wait for my approval.
  4. Tras aprobar el esquema, prompt: Create a complete Tutor1on1 course folder with contents.txt, one <id>_lecture.txt for every id, and optional easy/medium/hard question files. Run a self-check and list missing files.
  5. Descargue la carpeta o zip, descomprima y cargue esa carpeta en Tutor1on1.

Codex escritorio o GUI local

  1. Cree source_materials/ para documentos originales y una carpeta vacía como special_relativity_course/.
  2. Abra el workspace padre en Codex.
  3. Prompt: Use source_materials/ as input. Create a complete Tutor1on1 course folder in special_relativity_course/. Do not modify source_materials/. First generate contents.txt, then generate all lecture and question files. After writing files, check that every contents.txt id has <id>_lecture.txt.
  4. Deje que Codex escriba archivos directamente. Pida un informe final de self-check y luego cargue la carpeta de salida en Tutor1on1.

AI edit course dentro de Tutor1on1

  1. Después de cargar la carpeta, abra el skill tree del curso como profesor.
  2. Haga clic derecho en el KP o en su título y elija AI edit content.
  3. Elija Content para texto de lección o Question para texto del banco de preguntas del KP.
  4. Converse con la AI hasta que la última respuesta esté lista para guardar. Mantenga cada petición centrada en ese KP.
  5. Pulse Edit en la respuesta de AI para abrir la ventana diff. Revise el texto actual a la izquierda y edite la propuesta a la derecha.
  6. Elija Add para añadir o Replace para sobrescribir. Para preguntas, elija también easy, medium o hard.
  7. Guarde el cambio. Vuelva a subir el course bundle cuando quiera que los estudiantes del marketplace reciban el contenido actualizado.

Campos de API config

  • Provider elige el servicio de modelos, como OpenAI o SiliconFlow.
  • Base URL es el endpoint que Tutor1on1 usa para el proveedor seleccionado.
  • API Key se guarda localmente y se usa para tutor, TTS y STT cuando esas funciones lo necesitan.
  • Test API key llama a {baseUrl}/models, verifica la key y carga las listas de modelos text, TTS y STT disponibles. No descarga modelos ni selecciona automáticamente un modelo nuevo.
  • Text model alimenta la conversación del tutor. Thinking effort aparece solo si el provider admite controles de reasoning.
  • TTS model controla la salida de voz. STT model controla voz a texto. Pueden quedar vacíos si no usa voz.
  • Saved API configs guarda provider URL, modelos seleccionados, thinking effort y key hash para reutilizar configuraciones verificadas.

Usar ChatGPT OAuth en lugar de API key

  1. Abra Settings, API Settings, y elija OpenAI Codex (ChatGPT OAuth) como Provider.
  2. Pulse Login with ChatGPT y complete el inicio de sesión en el navegador. Si la app no vuelve automáticamente, pegue el redirect URL final o el authorization code en el diálogo.
  3. Pulse Refresh models, elija un text model como gpt-5.5 y guarde la API config.
  4. Inicie o vuelva a abrir una sesión de tutor y elija el modelo Codex OAuth guardado en el selector de modelos.

Esta opción usa ChatGPT/Codex OAuth quota para las conversaciones de texto del tutor. TTS y STT siguen usando providers con API key cuando se necesita voz.

Sync

Continuidad

Las páginas de profesor y estudiante sincronizan inscripciones, sesiones, progreso y señales del cuaderno de errores vinculadas a la cuenta.

Problemas comunes

  • Si falla el inicio de sesión o la carga del curso, compruebe que la app llegue a api.tutor1on1.org.
  • Si un estudiante no puede entrar a un curso, confirme que la inscripción fue aprobada y que el bundle se descargó.
  • Si la lista de modelos parece antigua, ejecute Test API key otra vez para el provider y key activos.
  • Si el progreso parece desactualizado entre dispositivos, espere a que termine la sincronización o ejecute una actualización manual.
